Diagnostic Methodology

IT Troubleshooting Portfolio

5 detailed troubleshooting logs grounded in real-world operational and web application incidents.

Problem:

USB barcode scanners in the warehouse terminal truncated 14-digit GTIN barcodes or inserted garbage ASCII characters during rapid scanning.

Possible Causes:
  • Serial USB baud rate mismatch or incorrect keyboard emulation delay (inter-character delay).
  • Missing carriage-return suffix (`CR/LF`) causing input concatenation in dispatch software.
Diagnostic Procedure:

Tested input raw stream in a plain text editor to isolate software vs. hardware buffer. Confirmed transmission delay was set too low (0ms).

Solution:

Scanned manufacturer configuration barcode to set a 20ms inter-character delay and appended automatic `Enter` (Suffix CR) terminator.

Lesson Learned:

Hardware peripherals require strict physical calibration and transmission throttling before integration into database ingestion interfaces.

Problem:

The order-taking display monitor froze during lunch rush, failing to render completed tickets and delaying drive-thru order assembly.

Possible Causes:
  • Memory leak in client-side web socket polling script accumulating uncleared DOM elements.
  • Network broadcast storm across POS Ethernet switch.
Diagnostic Procedure:

Examined task manager on the thin-client POS unit; discovered browser process consuming 98% RAM with 4,000+ detached DOM nodes.

Solution:

Refactored client script to destroy detached DOM elements and capped the local ticket buffer to the 50 most recent transactions.

Lesson Learned:

Always implement strict garbage collection and view caching on continuous-duty display terminals.

Problem:

Web application threw HTTP 500 error: "SQLSTATE[HY000] [1040] Too many connections" during simulated concurrent checkout testing.

Possible Causes:
  • Unclosed PDO database handles remaining open inside loops.
  • Default MySQL `max_connections` set too low (151) for burst traffic.
Diagnostic Procedure:

Executed SHOW PROCESSLIST; in MySQL CLI, revealing 150 persistent sleeping threads (`Command: Sleep`) with idle time > 300s.

Solution:

Implemented explicit database singleton pattern with persistent pooling, closed idle statements, and reduced `wait_timeout` to 30 seconds.

Lesson Learned:

Database connections are finite system resources; connection lifecycles must be closed immediately post-execution.

Problem:

Weekly stock reconciliation sheet containing 15,000 inventory rows showed #REF! and circular reference warnings, halting report delivery.

Possible Causes:
  • Accidental deletion of a referenced lookup column during manual sorting.
  • Dynamic relative cell referencing drifting during automated row insertions.
Diagnostic Procedure:

Used Excel's Formula Auditing toolbar (Trace Precedents and Error Checking) to pinpoint broken cell pointers.

Solution:

Converted static range formulas to Excel Structured Tables (`ListObject`) using explicit column headers: [@UnitPrice] * [@Qty] and protected formula cells.

Lesson Learned:

Enterprise spreadsheet models must utilize structured table references and worksheet protection to prevent catastrophic operator formula breaks.

Problem:

Customer payments were processed by the online payment provider, but the store order status remained stuck on "Pending Payment".

Possible Causes:
  • Webhook payload signature failing HMAC comparison due to trailing whitespace or character encoding differences.
  • HTTP 301 redirect stripping headers during server routing.
Diagnostic Procedure:

Logged incoming raw HTTP body using file_get_contents('php://input') and compared calculated hash against X-Signature header.

Solution:

Used exact raw binary string input for hash_hmac('sha256', $rawBody, $secret) rather than re-encoded JSON arrays, guaranteeing 100% hash parity.

Lesson Learned:

Cryptographic webhook verification must strictly operate on raw unparsed byte streams prior to any JSON decoding.

Cybersecurity & AI Literacy

Real-world mitigation of E-Commerce vulnerabilities and empirical AI audit verification.

Critical Flaw: Insecure Direct Object References (IDOR)

In e-commerce order lookups, failing to verify the authenticated user against the requested order ID enables malicious customers to inspect competitors' or other buyers' invoices by simply tampering with the URL parameter (e.g., /order_details.php?id=1052).

VULNERABLE BACKEND (No Ownership Validation) PHP 
// VULNERABLE: Direct access to order record without user check
$order_id = $_GET['order_id'];
$query = "SELECT * FROM orders WHERE id = $order_id"; // Also vulnerable to SQLi!
$result = $conn->query($query);
$order = $result->fetch_assoc();
// Returns ANY customer's private invoice and address!
Impact: Massive data exfiltration, privacy regulatory breach (DPA 2012), and customer address leakage.
Defensive Fix: Bound Parameter & Session Ownership

Enforce session-bound ownership validation where queries strictly mandate that the order_id must match the authenticated $_SESSION['user_id'] or require Administrator role clearance.

SECURE DEFENSE (PDO Parameterized Query + Ownership) PHP / PDO 
// SECURE: Enforces authentication + strict ownership check
$stmt = $pdo->prepare("SELECT * FROM orders 
                       WHERE id = :order_id 
                       AND (customer_id = :user_id OR :is_admin = 1) 
                       LIMIT 1");
$stmt->execute([
    'order_id' => $_GET['order_id'],
    'user_id'  => $_SESSION['user_id'],
    'is_admin' => ($_SESSION['role'] === 'admin' ? 1 : 0)
]);
$order = $stmt->fetch();
if (!$order) { http_response_code(403); exit('Access Denied'); }
Defense: Eliminates IDOR and SQL Injection simultaneously through strict session binding and PDO parameterization.

DATABASE ARCHITECTURE Topic: 3NF & ACID
How do you normalize a database to 3NF, and why does it matter?

"1NF eliminates repeating groups and enforces atomicity. 2NF removes partial dependencies (all non-key columns depend on the entire primary key). 3NF eliminates transitive dependencies (non-key columns must not depend on other non-key columns). In our E-Commerce database, separating Customer, Orders, and Order_Items into 3NF prevents update anomalies and guarantees that a price update does not corrupt historical order receipts."

Rule: Every non-key attribute must provide a fact about the key, the whole key, and nothing but the key.
CYBERSECURITY Topic: SQLi Defense
Why do Prepared Statements eliminate SQL Injection completely?

"Prepared statements compile the SQL query structure in the database engine before user parameters are bound. The database treats parameter values strictly as literal data, never as executable code. Even if an attacker injects ' OR 1=1 --, the database interprets it as a search string, making SQL manipulation impossible."

$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email"); $stmt->execute(['email' => $input]);
WEB SECURITY Topic: IDOR Mitigation
What is an IDOR vulnerability, and how do you protect against it?

"Insecure Direct Object Reference occurs when an application exposes a database key directly in client requests (e.g., ?invoice_id=450) without verifying if the authenticated user owns that record. Defense requires combining primary keys with session-bound ownership: WHERE order_id = :id AND (customer_id = :session_user_id OR :is_admin = 1)."

Always validate object ownership against server session cookies, never client parameters.
SYSTEM INTEGRATION Topic: HMAC Webhooks
How do you verify the authenticity of an incoming payment webhook?

"Payment providers send an X-Signature header containing an HMAC-SHA256 hash. The receiving server reads the raw binary byte stream via file_get_contents('php://input'), calculates the expected HMAC using the shared secret, and compares them with hash_equals() to prevent timing attacks. Re-serializing parsed JSON must be avoided because whitespace changes invalidate the hash."

$hash = hash_hmac('sha256', $rawBody, SECRET_KEY); if (hash_equals($hash, $headerSig)) { ... }
NETWORKING & HARDWARE Topic: Buffer Overruns
How do you diagnose and fix barcode scanner character drops?

"When serial-over-USB scanners transmit 14-digit GTIN barcodes with 0ms transmission delay, high scanning frequency overwhelms the operating system's keyboard input buffer, dropping characters. Diagnosis is performed via serial monitor (PuTTY). The solution is scanning manufacturer configuration barcodes to set an inter-character transmission delay of 20ms and adding a persistent CR/LF terminator."

Calibrate inter-character delay (20ms) + persistent CR/LF suffix on industrial input peripherals.
FRONTEND ARCHITECTURE Topic: DOM Memory Leaks
What causes browser freeze on continuous POS displays and how to prevent it?

"Continuous long-polling scripts that dynamically create and remove HTML elements without explicitly unbinding event listeners generate detached DOM nodes. These remain pinned in JavaScript memory, eventually exhausting system RAM (consuming 3.5GB+). Prevention requires unbinding event listeners, implementing circular rendering queues, and explicitly invoking garbage collection."

element.removeEventListener('click', handler); element.remove(); circularQueue.cap(50);
